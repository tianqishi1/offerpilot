# 求职 Agent 技术实现方案

产品代号：OfferPilot · 职航 ｜ 版本 v0.1 ｜ 2026-11-18
前置文档：《求职Agent产品设计方案.md》（含附录 B/C：适配器对比、20 家抽样、API 获取模型核实）

> 本方案落实抽样后的修正结论：
> **P0 = 通用 LLM-DOM 适配器 + 自研标杆（百度/美团）；P1 = 飞书/Moka 标准适配器；P2 = 北森适配器族。**
> 聚合不依赖任何企业授权 API；主路径 = 用户端采集 + 公开源。
> 形态 = Chrome/Edge MV3 插件（主）+ Web 工作台（辅）+ 轻量云端。
> 团队假设：2 名工程师（E1 插件/执行引擎，E2 后端/LLM/匹配），6 周 MVP。

## 0. 技术决策总览（ADR 摘要）

| # | 决策 | 选择 | 理由 / 放弃项 |
|---|---|---|---|
| D1 | 插件框架 | **WXT + React + TypeScript（MV3）** | 一套代码出 Chrome/Edge；内置 content/sidepanel/background 工程化。放弃 Plasmo（商业许可顾虑）、裸 MV3（工程量大） |
| D2 | 填表执行位置 | **content script（isolated world）DOM 级操作** | native setter+合成事件在隔离世界即可生效；不注入 MAIN world 改框架内部，降低风控/审计风险 |
| D3 | 简历解析 | **端侧优先**：pdf.js / mammoth 本地抽文本；图片 OCR 走云端（单独同意，原图即删） | 兑现"本地优先"；云端只收用户确认后的脱敏结构化画像 |
| D4 | 云端框架 | **Fastify + Zod + OpenAPI**（Node 22 LTS） | 2 人团队轻量为王；放弃 NestJS（样板多） |
| D5 | 存储 | **Postgres 16 + pgvector**；Redis + BullMQ（异步任务）；OSS（导出件） | 匹配向量与业务数据同库，省运维 |
| D6 | LLM | **分层 + OpenAI 兼容网关**：抽取/映射用小模型档（Qwen-flash 级），生成/复核用大模型档（Qwen-plus/max、DeepSeek-V3、GLM-4 级），embedding 用 text-embedding-v4 级；**国内端点，数据不出境** | 成本与合规；具体型号以实施时目录为准，网关抽象可换 |
| D7 | 结构化输出 | **JSON Schema 约束 + Zod 校验 + 最多 2 次重试 + 降级** | FillPlan/匹配分/简历改写全部结构化，杜绝自由文本进执行引擎 |
| D8 | 适配器分发 | **服务端指纹注册中心 + 热更新**（签名 JSON），执行代码随插件发版 | schema/指纹/提示词可热修，无需商店审核；执行器代码变更走商店（1-3 天） |
| D9 | PDF 导出 | **服务端 Playwright 渲染 HTML 模板 → PDF**，回传 Blob 存本地 IndexedDB | 字体/排版一致；原始简历文件永不上传 |
| D10 | 权限模型 | **optional_host_permissions + 按站点动态授权** | 首次在某 ATS 使用时才请求该域名权限；商店审核友好、隐私最小化 |
| D11 | 提交校验 | **适配器成功特征 + 通用启发式 + 状态页回查**；邮件校验 V1.1 单独授权 | 反"草稿幻觉"；只有 verified 计入有效投递 |
| D12 | 遥测 | **漏斗事件匿名化、默认不含 JD/简历内容、opt-in** | PIPL 最小必要；飞轮用聚合统计而非原文 |

## 1. 总体架构

```
┌─ 用户浏览器（Chrome/Edge, MV3）────────────────────────────────┐
│ sidepanel (React)      岗位卡片/填写进度/置信度/提交预览        │
│ background (SW)        适配器调度/状态机/注册中心同步/消息路由  │
│ content scripts        DOM提取 / 执行引擎 / 页面指纹 / 校验     │
│   ├ 动态注册：用户授权某域名后 chrome.scripting.register…      │
│   └ 隔离世界执行；不读 cookie、不碰平台凭证                    │
│ IndexedDB (Dexie)      画像/简历Blob/FillPlan快照/投递记录      │
│   └ WebCrypto AES-GCM 加密（设备绑定非导出密钥）               │
│ 本地解析               pdf.js / mammoth（文本层）              │
└──────────────┬───────────────────────────────────────────────┘
               │ HTTPS（仅脱敏画像+JD+字段schema+生成请求）
               ▼
┌─ 云端 ───────────────────────────────────────────────────────┐
│ Fastify API ── auth/consent/profile/jobs/match/tailor/        │
│               fillplan/registry/applications/events/billing   │
│ BullMQ workers ── 解析增强/批量匹配/简历生成/PDF渲染/评测      │
│ LLM Gateway ── 分层路由/JSON Schema/重试/缓存/预算/提示词版本  │
│ Postgres+pgvector ── 业务+向量 │ Redis ── 队列/缓存/限流       │
│ OSS ── 导出PDF/模板 │ 注册中心 ── 指纹/schema/提示词(签名)     │
└──────────────────────────────────────────────────────────────┘
```

**数据边界（硬规则）**
- 不出浏览器：平台 cookie/登录态、身份证/手机号等敏感字段、原始简历文件、FillPlan 的字段值快照。
- 可上云（用户确认后）：脱敏结构化画像（教育/实习/项目/技能，去除敏感字段）、JD 文本、字段 schema（label/kind/required，不含值）、生成请求。
- 云端不留：原始简历文件、敏感字段、页面截图。FillPlan 云端只存元数据（fieldId/source/confidence/模型版本），值留在本地。

## 3. 核心契约（packages/core）

### 3.1 FillPlan（执行引擎唯一输入）

```ts
// 所有 schema 用 Zod 定义，JSON Schema 由 zod-to-json-schema 导出给 LLM
export const ValueSource = z.enum(['profile', 'generated', 'user', 'missing']);

export const FieldPlan = z.object({
  fieldId: z.string(),                 // 页面内稳定 id（extract 生成）
  kind: z.enum(['text','textarea','select','combobox','radio','checkbox',
                'date','file','richtext','custom']),
  label: z.string(),
  required: z.boolean(),
  selectors: z.array(SelectorStrategy).min(1),   // 弹性定位链，见 3.2
  value: z.object({
    source: ValueSource,
    profilePath: z.string().optional(),          // source=profile：画像 JSONPath
    generatedId: z.string().optional(),          // source=generated：生成内容 id（含溯源）
    text: z.string().optional(),                 // 待执行文本（本地组装，不上云）
    fileRef: z.string().optional(),              // source=file：本地 Blob 引用
  }),
  confidence: z.number().min(0).max(1),
  status: z.enum(['pending','filled','needs_review','missing','failed','confirmed']),
  traceability: z.object({                       // 事实护栏
    resumeItemIds: z.array(z.string()).optional(),
    jdKeywords: z.array(z.string()).optional(),
  }).optional(),
  validation: z.array(z.object({                 // 执行后校验规则
    type: z.enum(['nonempty','maxLength','pattern','optionExists','fileAccepted']),
    args: z.record(z.any()).optional(),
  })).optional(),
});

export const FillPlan = z.object({
  id: z.string(),
  adapterId: z.string(), adapterVersion: z.string(),
  pageFingerprint: z.string(),                   // 注册中心指纹 id
  applicationId: z.string().optional(),
  pages: z.array(z.object({                      // 多页表单：逐页计划
    pageIndex: z.number(),
    fields: z.array(FieldPlan),
    next: z.object({ selectors: z.array(SelectorStrategy),
                     waitUntil: z.enum(['navigation','domStable','selector']) }),
  })),
  submit: z.object({
    selectors: z.array(SelectorStrategy),
    verify: VerifySpec,                          // 见 3.5
  }),
  meta: z.object({ modelTier: z.string(), promptVersion: z.string(),
                   schemaHash: z.string(), createdAt: z.string() }),
});
```

### 3.2 SelectorStrategy（弹性定位 + 自愈）

```ts
export const SelectorStrategy = z.discriminatedUnion('type', [
  z.object({ type: z.literal('label'),    value: z.string() }),  // label[for]/包裹文本
  z.object({ type: z.literal('aria'),     role: z.string(), name: z.string() }),
  z.object({ type: z.literal('css'),      value: z.string() }),
  z.object({ type: z.literal('xpath'),    value: z.string() }),
  z.object({ type: z.literal('placeholder'), value: z.string() }),
  z.object({ type: z.literal('nameAttr'), value: z.string() }),
]);
// 执行时按链依次尝试；命中非首选项 → 上报 drift 事件（注册中心告警）
```

### 3.3 Adapter 协议

```ts
export interface AtsAdapter {

  fingerprints: FingerprintRule[];               // 注册中心下发，见 §6
  detect(ctx: PageContext): Promise<DetectResult | null>;

// generic 适配器实现全部；专用适配器可复用 generic 的 extract/execute，
// 仅覆盖 fingerprints / 定制组件 / verify 特征 / 解析借力路径。
```

### 3.4 Application 状态机（与产品 M5 一致）

```

      → test → interview → offer → closed(rejected|withdrawn|ghosted)
submitted 未 verified：单独提示，不计入有效投递统计。
状态迁移全部带时间戳+来源（plugin_detect|user_manual|email_v1.1），本地权威，云端同步元数据。
```

## 4. 通用 LLM-DOM 适配器（P0 核心）

### 4.1 字段提取 extract()
1. 遍历渲染后 DOM：`input/select/textarea/[contenteditable]/[role=combobox|listbox|radio|checkbox]` + 自定义组件（含 role/aria 的 div）。
2. 标签关联：`label[for]` → `aria-labelledby` → 包裹 label → 最近前置文本节点（启发式，带置信度）。
3. 输出 FieldSchema：`{fieldId, kind, label, required, options?, maxLength?, accept?, groupPath(多段表单), selectors[]}`。
4. 同时采集页面指纹输入：domain/path/特征参数（channelToken、/campus-recruitment/、jobs.feishu.cn 等）+ 关键 DOM 标记。
5. **不采集值**（用户已填内容不外传）；截图仅本地可选。

### 4.2 计划生成 buildFillPlan()
- 输入：FieldSchema[] + 脱敏画像 + JD。
- **事实字段**（姓名/教育/实习/技能/日期）：小模型档做 schema→profilePath 映射（JSON 输出），**值在本地按 profilePath 组装**，云端不接触敏感值。
- **开放题**（"为什么选我们/职业规划"）：大模型档生成，强制 traceability（引用 resumeItemIds + jdKeywords），status=needs_review。
- **knockout/敏感**（学历真实性/签证/竞业/期望薪资）：一律 source=user 或 missing，**禁止 AI 代答**。
- 缺失字段：source=missing，标红。
- 置信度：映射模型自评 × 规则校验（label 相似度/选项存在性）→ 绿(≥0.9 直填)/黄(0.6-0.9 待确认)/红(<0.6 或缺失)。
- 缓存：schemaHash+profileVersion+JD hash → 计划模板（值本地填充），命中省 80% token。

### 4.3 执行引擎 execute()（packages/executor，关键代码）

```ts
// (a) React 受控组件：native setter + 事件 + valueTracker 复位
function setNativeValue(el: HTMLInputElement | HTMLTextAreaElement, value: string) {
  const proto = el instanceof HTMLTextAreaElement
    ? HTMLTextAreaElement.prototype : HTMLInputElement.prototype;
  const setter = Object.getOwnPropertyDescriptor(proto, 'value')!.set!;
  setter.call(el, value);
  // React 16+ _valueTracker 会吞掉重复值，先复位
  const tracker = (el as any)._valueTracker;
  if (tracker) tracker.setValue('');
  el.dispatchEvent(new Event('input',  { bubbles: true }));
  el.dispatchEvent(new Event('change', { bubbles: true }));
}

// (b) 文件上传：DataTransfer 构造 FileList（简历 PDF 来自本地 IndexedDB Blob）
async function attachFile(input: HTMLInputElement, blob: Blob, name: string) {
  const file = new File([blob], name, { type: blob.type });
  const dt = new DataTransfer();
  dt.items.add(file);
  input.files = dt.files;
  input.dispatchEvent(new Event('change', { bubbles: true }));
  // 拖拽区兜底：对 dropzone 派发 dragenter/dragover/drop（携带同一 dt）
}

// (c) combobox / React Select：search → 等选项 → select
async function pickCombobox(el: HTMLElement, optionText: string) {
  el.focus();
  setNativeValue(el as HTMLInputElement, optionText);         // 触发搜索
  const opt = await waitForOption(el, optionText, 3000);      // MutationObserver 等 listbox
  if (!opt) throw new FieldError('option_not_found');         // → 标黄交人工
  opt.click();                                                // 或 keydown ArrowDown+Enter
  await waitForSelected(el, optionText);                      // aria-activedescendant/选中态
}

// (d) 多页状态机：逐页 extract→fill→next→waitUntil→重提取；进度持久化到 IndexedDB，
//     页面刷新/跳转可恢复；每页独立 FillPlan.pages[i]。
// (e) 拟人节奏：字段间 50-200ms 随机延迟；整表完成不自动提交（永远人工点击）。
// (f) 每字段执行后跑 validation 规则；失败重试 1 次 → status=failed 标红，不阻塞其他字段。
```

执行报告 ExecutionReport：逐字段 `{fieldId, status, attempts, driftUsed, error?}` → 本地审计快照 + 匿名聚合遥测（成功率/漂移率，不含值）。

### 4.4 提交与校验
- 用户在 sidepanel 全量预览（黄/红字段必须处理或显式跳过非必填）→ 点"确认提交"。
- 执行 submit.selectors.click() → verifySubmit()：URL 特征 / 成功文案 / 成功元素 / 表单消失，多证据加权；≥2 项命中 → verified；仅 1 项 → unverified（提示用户去状态页/邮箱确认）；0 → failed（引导手动）。
- verified 后写 Application(submitted→verified)，记录 resumeVersion + FillPlan 快照 id。

### 4.5 自研标杆（百度/美团）
- 复用 generic extract/execute，仅补充：站点专用指纹、日期/城市级联组件定制、成功页特征、状态页 trackStatus。
- 目的：把 generic 在真实高频站点打磨到字段准确率 ≥95%，沉淀夹具进回归 suite。

## 5. 飞书 / Moka 标准适配器（P1）

### 5.1 指纹（注册中心初始条目，承接附录 C.6）
```
feishu: *.jobs.feishu.cn | *.jobs.f.{私有域名}(如 mioffice.cn)
        path: /campus /{org}campus /s/{code} /m/position/detail/{id}
moka:   app.mokahr.com | app-tc.mokahr.com
        path: /campus-recruitment/{org}/{id} | /su/{code}
        param: channelToken= ；自定义域名 + 上述 path/param 组合
beisen: *.zhiye.com（子域=租户） path: /campus /personal/deliveryRecord  (P2)
```

### 5.2 飞书适配器
- 门户高度统一（{org}.jobs.feishu.cn），一套 extract schema 覆盖多租户；私有化域名（小米 mioffice）走同一指纹族。
- 表单为标准 React 组件 + 少量定制；执行引擎通用路径即可。
- trackStatus：候选人个人中心投递记录页（同域）。

### 5.3 Moka 适配器（含"借力解析"主路径）
- **路径 A（优先）上传简历→平台解析→校验补全**：
  1. 定位上传 input → attachFile(定向简历 PDF)；
  2. 等待平台解析完成（loading 消失/字段出现，MutationObserver）；
  3. 重新 extract → 与画像逐字段比对（diff）→ 不一致标黄、空缺补填；
  4. 开放题走生成路径；预览确认提交。
  - 优点：字段级工程量最小、天然绕开受控组件坑、解析准确率借平台能力。
  - 风险：平台解析错配 → diff 校验兜底；解析失败 → 自动降级路径 B。
- **路径 B（兜底）**：generic 逐字段填写。
- 指纹注意：/su/ 短链会 302 到标准门户；channelToken 参数在自定义域名（B站/米哈游待实测）同样出现 → 指纹库组合判定。

### 5.4 北森适配器族（P2 占位）
- zhiye.com 子域指纹 → 租户 schema 覆盖表（注册中心下发）；定制组件/附件/内推码/多步表单专用执行分支；通用兜底。
- 触发条件：用户群扩展到制造/国企/金融（抽样显示 P0 人群占比 0）。

## 6. 指纹注册中心与热更新

```jsonc
// registry.json（服务端签名下发，插件启动+每日同步）
{
  "version": "2026.11.18-1",
  "adapters": [{
    "id": "moka", "minExecutorVersion": "1.2.0",
    "fingerprints": [
      { "domains": ["app.mokahr.com","app-tc.mokahr.com"],
        "pathRegex": "^/(campus-recruitment|su)/", "weight": 1.0 },
      { "paramExists": ["channelToken"], "pathRegex": "/campus", "weight": 0.8 }
    ],
    "fieldSchemaOverrides": { /* 租户/版本级字段映射 */ },
    "verifyPresets": { /* 成功特征 */ },
    "promptVersions": { "map": "v3", "generate": "v5" }
  }],
  "fallback": "generic",
  "killSwitch": { "adapters": [], "features": [] }   // 紧急下线某适配器/功能
}
```
- **漂移监测**：执行失败率/选择器降级率按 adapterId×version 聚合 → 阈值告警 → 自动降级 generic + killSwitch 可选。
- **迁移监测**：用户端匿名上报"域名 X 命中指纹 Y"聚合计数（无内容）→ 发现小米式迁移（Moka→飞书）→ 更新注册中心，无需发版。
- 待实测项（B站/米哈游/滴滴）：内测期插件抓指纹回传聚合，确认后入库。

## 7. 匹配管线（packages/matching）

```
Job 入库（用户端采集/公开源，含来源+时间戳+去重 hash）
 → 硬过滤：城市/学历/毕业年份/签证/截止日（SQL）
 → 向量召回：pgvector cosine(embed(JD), embed(profile)) top-50
 → LLM 复核（大模型档，批量 JSON）：
    { score:0-100, dims:{skill,experience,competition,timing},
      gaps:[{missing, severity, suggestion}], reasons:[...] }
 → 排序：score × 时效权重（截止临近↑、发布新鲜↑）
 → 每日精推 3-5（sidepanel/日报），附适配报告
```
- embedding：JD 与画像分别向量化；profile 更新触发重算（BullMQ）。
- 竞争/时效启发式：发布时长、截止日、（若页面可见）投递人数。
- 飞轮：OutcomeEvent（回复/面试/offer，用户标记，匿名聚合）→ 定期校准维度权重与 rerank rubric（离线评测 NDCG 达标才上线）。
- 合规：公开源标注来源；用户端采集等价浏览；不做服务端集中爬取。

## 8. 定向简历管线（packages/tailor）+ 事实护栏

```
JD → 关键词/能力项抽取（小模型）
 → 条目选择与重排（约束：只能从 resume_items 选，禁止新增）
 → bullet 润色改写（大模型，逐条带 traceability.resumeItemId）
 → ATS 关键词覆盖检查（规则）
 → 事实性校验（双重）：
    a) 规则：实体 diff（公司/学校/日期/数字/技能词）不得新增；
       动词语义升级拦截（参与→负责/主导 等黑名单映射）
    b) LLM entailment：改写句 vs 原句 蕴含判定，不蕴含→打回
 → diff 预览（用户可编辑/回退）→ 确认
 → 服务端 Playwright 渲染 HTML 模板 → PDF → Blob 回传本地 IndexedDB
 → 与 Application 绑定 resumeVersion（可回溯"当时投的哪版"）
```
- 求职信/开放题同护栏；无法溯源的内容一律标"需你补充"，不进自动填充。
- 评测：事实错误率 <1%（抽检+entailment 测试集），作为上线门禁。

## 9. LLM 网关（packages/llm）

- **分层路由**：extract/map/classify → 小模型档；generate/rerank/entailment/mock-interview → 大模型档；embedding → 向量档。型号配置化（国内端点），可热切换。
- **结构化输出**：统一 `call(schema, prompt, tier)` → JSON Schema 约束 + Zod 校验 + 2 次重试 + 降级（大模型失败→小模型简化 schema→人工兜底）。
- **提示词版本化**：promptVersion 随注册中心下发；FillPlan.meta 记录，便于回归定位。
- **缓存**：JD 解析（hash）、schema→映射模板（schemaHash+profileVersion）、匹配分（profileVersion+JD hash）。目标命中率 ≥60%。
- **预算与限流**：per-user 月度 token 预算（免费层硬限额）；全局 QPS 限流；成本看板按用户/功能聚合。
- **成本估算（单活跃用户/月）**：解析+映射 ~¥1-3；匹配复核 ~¥2-5；简历/开放题生成 ~¥3-8；模拟面试(V1.2) ~¥2-5 → 合计 ¥5-20，对照 ¥69/月毛利充足。

## 11. 插件工程细节（apps/extension）

- **WXT 入口**：background(SW) / content(动态注册) / sidepanel(React)。
- **权限**：`optional_host_permissions: ["*://*/*"]` + activeTab；用户在某 ATS 首次点"填写"→ `chrome.permissions.request({origins})` → 成功后 `chrome.scripting.registerContentScripts` 该域名。商店审核说明"按站点授权、不读 cookie、不自动提交"。
- **消息协议**（core 定义，zod 校验）：
  `content ↔ background：DETECT/EXTRACT/EXECUTE_FIELD/EXECUTE_PLAN/VERIFY/SNAPSHOT`
  `sidepanel ↔ background：PLAN_REQUEST/PROGRESS/CONFIRM_SUBMIT/STATUS`
  `background ↔ server：registry/profile/fillplan/tailor/events（fetch，JWT）`
- **本地存储**：Dexie(IndexedDB)：profile(加密)、resumes(Blob)、fillplans(快照)、applications(镜像)、settings。密钥：WebCrypto 生成非导出 AES-GCM CryptoKey 存 IndexedDB（设备绑定）；敏感字段仅存本地加密区。
- **恢复与幂等**：多页进度持久化；EXECUTE_FIELD 幂等（先读当前值，相等则跳过）；页面刷新后按 pageIndex 恢复。
- **审计**：每次执行存 FillPlan 快照+ExecutionReport（本地）；用户可导出/回放；云端只收聚合成功率。
- **不做什么**：不读/不传 cookie；不注入 MAIN world 改框架；不自动点击提交；不绕过验证码/监考。
