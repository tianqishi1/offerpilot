# 求职 Agent 可行性调研报告

日期：2026-11-18 ｜ 调研方式：公开资料检索（产品官网、GitHub、行业报告、平台政策、媒体评测）

---

## 一、总体结论（TL;DR）

**可行，但方向必须选对：**

- ✅ **"人机协同的求职 Copilot"**（岗位聚合匹配、定向简历、网申自动填写、进度管理、模拟面试，关键动作由人确认）：技术成熟、需求真实、国内外均已有付费验证。**建议做这个。**
- ⚠️ **"全自动无人值守海投机器人"**（批量打招呼、自动投递、自动与 HR 聊天）：技术上能做，但处于平台风控强对抗位、实际效果差、有法律与封号风险。**不建议作为核心卖点。**

一句话定位：**做"提高单次投递质量 + 节省时间"的 Agent，而不是"增加投递数量"的 spam 机器。** 数据表明数量不是杠杆，匹配质量、简历定制和跟进才是。

### 2.4 平台官方动向（决定赛道边界）

- **LinkedIn**：官方帮助页明确禁止第三方 bot/爬虫/浏览器插件，自动化行为会导致账号受限；但官方自己推出了 **Hiring Assistant 2**（招聘者侧 Agent）。
- **BOSS直聘**：AI 风控持续加码——2026 年 3 月封禁 1.3 万虚假引流账号（约 90% 在举报前被 AI 主动拦截）；2026 年 6-7 月冻结 2.5 万违规账号（95%+ 由 AI 识别）；用**语义识别 + 行为建模**专打"批量操作、相同话术、异常频率"。
- **北森**等 B 端厂商推出 5 大招聘 Agent；BOSS直聘官方 AI agent 让招聘者效率提升 25%。

> **关键洞察：平台把"Agent 化"留给了官方和 B 端。求职者侧的第三方全自动操作，天然处于与平台对抗的位置；而"帮用户填表、改简历、管理进度"这类不触碰平台账号行为的功能，对抗性低得多。**

## 三、效果数据：海投无效，精准 + 定制才有效

这是本次调研最重要的发现，直接决定产品定位：

1. **Huntr 2026 Q2 报告**（102,777 次投递 / 5,388 名用户，2026.4-6）：
   - 开始求职到首个面试中位数 **23 天**，到首个 offer **82 天**；
   - 单次投递面试率：**不定制简历 3.09% vs 定制简历 5.71%**（接近翻倍）；
   - 每季度精投 11-20 个的用户面试率 **8.12%**，大量海投的用户仅 **2.86%**。
2. 行业平均冷投递回复率约 **2-3%**（LoopCV 2026 统计）。
3. **Forbes 报道**：招聘方视角下，auto-apply 工具的单次投递成功率可低至 **0.01%**。
4. **2026 年 5 月实测 8 个自动投递工具：只有 3 个真正完成了 submit**，其余填完表就停在"草稿"状态——用户仪表盘显示"已投递"，雇主系统里根本没有这份申请。这是"投了几百个没回音"的最大技术原因。
5. **2026 年 3 月对 2000+ 美国招聘经理的调研**：67% 认为 AI 生成的申请拖慢了招聘，1/5 延迟超过两周，65% 表示更难验证候选人真实技能 → 雇主反制：增加 knockout 问题、提高资格门槛、**回流内推**。

> **结论：自动海投是"公地悲剧"——每个机器人都在让所有人的漏斗更紧。产品的真正杠杆是：匹配精度、简历定制、及时跟进、面试准备。Agent 应该优化"每次投递的转化率"，而不是"投递总数"。**

## 四、技术可行性评估（分模块）

| 模块 | 难度 | 成熟度 | 说明 |
|---|---|---|---|
| 简历/JD 解析、用户画像 | 低 | 成熟 | LLM 结构化抽取，直接做 |
| 岗位聚合 + 匹配打分 | 中 | 成熟 | **数据源是难点**：官方 API 极少，爬取受限；可用"聚合公开源 + 用户本地浏览器采集"混合 |
| 定向简历/求职信生成 | 低-中 | 成熟 | 面试率提升的最大杠杆（3.09%→5.71%），必须做好 |
| 网申表单自动填写（Workday/Greenhouse/Lever/北森/Moka/企业官网） | 中-高 | 已有成熟方案 | 长尾表单碎片化是主要工程量；**必须在真实浏览器里做**（服务端爬虫看不到渲染后的 React 表单）；Workday 私有组件、React Select  combobox、文件上传（DataTransfer API）、多页流程、CSRF token 都是已知坑，均有公开解法 |
| 平台内自动沟通（Boss 打招呼/聊 HR） | 中 | 可行但强对抗 | 开源和商业产品都实现了；但行为建模风控专打此类操作，封号是大概率事件，需节流+熔断+人工确认 |
| 投递进度追踪/日报/跟进提醒 | 低 | 成熟 | 用户粘性核心，面灵的"自动跟进"数据（18% 回复率）证明跟进有价值 |
| 模拟面试 + 评估报告 | 低-中 | 成熟 | 职芽的数字人面试官是差异化样例 |

### 推荐架构（规避主要技术/风控风险）

```
用户本地端（Chrome 插件 或 桌面客户端，复用用户自己的登录态与住宅 IP）
  ├─ DOM 提取：渲染后的表单字段 + 职位信息
  ├─ 填表执行：React native setter + 合成事件 / DataTransfer 文件上传
  └─ 人工确认闸门：提交前预览，一键确认
云端 / 本地 LLM 服务
  ├─ 画像与匹配打分（向量 + LLM 复核）
  ├─ 定向简历 / 求职信 / 问答生成
  └─ 投递漏斗数据回流（投了→回复→面试→offer，形成数据飞轮）
```

要点：
- **不做服务端集中爬取/代投**：机房 IP 被 Boss 等平台直接拦截（get_jobs 明确验证过），且集中代投法律风险最高。
- **登录态留在用户本地**，加密存储；简历数据最小化上传。
- LLM 成本可控：单用户每月几元到几十元人民币量级（解析+匹配+生成），相对 ¥99/月 或 $39.99/月 的定价毛利充足。

## 五、风险清单（按严重度排序）

| 风险 | 等级 | 说明与对策 |
|---|---|---|
| **平台风控/封号/接口失效** | 高 | Boss AI 风控（语义+行为建模）、LinkedIn 明确禁止自动化；开源项目"封号来得快"是真实反馈。对策：核心功能不依赖平台内自动操作；涉及打招呼/沟通时严格限速、随机间隔、每日上限、受限即熔断、用户显式授权；明确告知风险 |
| **效果反噬（spam 化）** | 高 | 雇主增加门槛、回流内推；海投类产品口碑恶化。对策：定位"精投+定制"，用面试率而非投递数作为北极星指标 |
| **法律合规** | 中-高 | 简历属个人信息（PIPL：告知同意、最小必要、存储安全；用境外 LLM API 涉及出境评估）；商业爬取/代投可能触及反不正当竞争法与平台协议；get_jobs 用非商业许可正是规避此风险。对策：本地优先架构、用户自有账号操作、不代管账号、不批量抓取转售 |
| **竞争同质化** | 中-高 | 海外 Jobright/Simplify 已占位，国内 Offer快/面灵/职芽/UP 已入场，开源方案门槛低。对策：垂直人群切入 + 结果数据飞轮 + 渠道（参考职芽的 B2B2C） |
| **用户留存/付费周期** | 中 | 找到工作即流失，强季节性（校招/金三银四）。对策：按求职季订阅、扩展到面试辅导/职业规划等长周期服务 |
| **LLM 幻觉与错误投递** | 中 | 填错表、答错 knockout 问题、生成不实经历。对策：提交前人工确认、事实性字段只从用户简历取值、禁止编造 |
| **数据源稳定性** | 中 | 平台改版/反爬升级导致聚合失效。对策：多源冗余 + 用户端采集兜底 |

## 六、商业模式参考

- **海外**：订阅制 $10-50/月，或按投递量计费（FastApply 约 5-7 美分/次）；Jobright $5M ARR 证明付费意愿真实存在。
- **国内**：面灵 ¥99/月、¥199/季（网申+Boss 沟通打包）；职芽先免费攒口碑再分层付费；Offer快内测申请制。
- **获客**：小红书/即刻/校园渠道/开源社区引流是主流；职芽证明"有 B 端/高校渠道则 CAC 趋近于零"。
- **建议定价**（若做国内）：免费层（解析+匹配+每日限量 autofill）→ ¥49-99/月（不限量网申+定制简历+跟进）→ 求职季卡/校招套餐。

## 七、建议的产品定位与 MVP 路线

### 定位建议（三选一，按推荐度排序）

1. **校招/应届生求职 Copilot**（推荐）：网申自动填写 + 岗位聚合匹配 + 定向简历 + 进度管理 + 模拟面试。理由：痛点最集中（大厂网申表单繁琐）、平台对抗最弱（企业官网/ATS 而非 Boss 账号行为）、职芽已验证需求但市场远未饱和、校园渠道可复制。
2. **海外求职/华人出海 Copilot**：Workday/Greenhouse/Lever autofill + LinkedIn 合规辅助（不自动操作 LinkedIn）+ 定制简历。理由：付费能力强（$39.99/月已被验证），Simplify 免费但自动提交弱，存在"真正能提交"的质量空档。
3. **Boss/猎聘半自动沟通助手**（不推荐首发）：需求真实（get_jobs 8.4k stars）但封号风险与合规风险最高，适合作为后期可选模块而非核心。

### MVP（约 4-6 周，1-2 人）

- **W1-2**：简历解析 + 画像；Chrome 插件骨架；选 1-2 个高频 ATS（如 Greenhouse/Lever 或国内北森/Moka）做 DOM 提取→LLM 填表计划→回填执行，**提交前人工确认**。
- **W3-4**：岗位聚合（公开源+用户端采集）+ 匹配打分 + 定向简历生成；投递记录与漏斗看板。
- **W5-6**：每日求职日报、未回复跟进提醒（提醒而非自动发送）、模拟面试问答；小范围（20-50 名真实求职者）内测。
- **北极星指标**：用户"投递→面试"转化率（对照 Huntr 基线 3.09%），以及单份网申节省时间（目标：30 分钟→3 分钟）。
- **红线**：不做无人值守批量提交；不集中代管账号；不编造简历内容；涉及平台内操作一律用户授权+限速+熔断。

### 长期壁垒

- **结果数据飞轮**：投递→回复→面试→offer 的全漏斗数据回流，持续优化匹配与简历策略（Jobright/职芽都在讲这个故事，但真正拥有闭环数据的玩家很少）。
- **垂直 know-how**：特定行业/岗位的 knockout 题库、面试题库、薪资谈判策略。
- **渠道**：高校/企业/社区合作，降低 CAC。

## 八、最终判断

| 维度 | 评估 |
|---|---|
| 技术可行性 | ✅ 高。所有核心模块均有成熟公开方案，工程量集中在长尾表单适配与数据源维护 |
| 需求真实性 | ✅ 高。求职是高频刚需痛点，开源项目热度与商业产品 ARR 双重验证 |
| 商业可行性 | ✅ 中高。$5M ARR / ¥99 月卡已验证付费；但留存短、季节性强，需精细运营 |
| 全自动海投路线 | ❌ 低。封号 + 草稿失败 + 雇主反制 + 效果数据差，四重否定 |
| 人机协同 Copilot 路线 | ✅ 推荐。对抗弱、价值实、可差异化 |
| 竞争窗口 | ⚠️ 中。巨头与创业公司已入场，但垂直场景（校招/出海/特定行业）仍有空档；纯通用工具无壁垒 |

**结论：做，但以"人机协同、精投定制、本地优先"的 Copilot 形态切入垂直人群；把"全自动海投"从产品愿景中划掉。**
